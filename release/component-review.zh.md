# 组件来源

1.2.36 的签名清单固定 743 个输入的 SHA-256，其中 691 项从仓库读取，包括依赖及两份合成编码统计样本。另有 52 项从用户的官方镜像生成。

### 16K Fast RAW

构建器校验官方 ISP 库，从双眼 120 MP 拍照描述符读取 41 个浮点参数，供色差校正、锐化和噪声回加使用。转换时从每张 DNG 读取 ISO、曝光和白平衡，原样保留颜色矩阵和四张镜头增益图。算法内部使用单位工作矩阵，可选的内部阴影表留空。

历史原厂引擎在一张参考图上分别替换工作矩阵、停用内部阴影表，双眼各自均为零像素变化。桌面回放使用已记录的推理输出，三张成片与参考 DNG 逐字节一致，验证了双眼输入、输出拼合及显色标签。原片中尚未找到可核实的原生照度索引，目前使用基础照度档；新参数组合在暗场和高增益下的实际推理画质还需验证，当前只用于锁定预览。

### 怎样核对媒体服务

[媒体服务配方](../openx6/mediad_recipe.py)列出了每层可执行文件的 SHA-256。[C 和 AArch64 源码](../recipes/mediad/)按顺序编译，包括后来被新入口取代、但仍占用目标文件字节的旧代码。某层不匹配时，构建会报告层名并中止。未选第三方媒体模块时，候选包内 `/usr/bin/ins_mediad` 的预期 SHA-256 为 `95eca63e20c111e49160bdef896d85bfe7939726af997e0ebc70ba4761cd8f9a`。若选了媒体模块，会在这一步校验通过后再应用，最终摘要记录在 `release-inputs.json`。

### 怎样核对相机 HAL

[HAL 配方](../openx6/camera_hal_recipe.py)从[曝光、HNR 和间隔拍照源码](../recipes/camera_hal/)编译。安装在 `/usr/lib/hw/camera.qcom.so` 的基础库 SHA-256 为 `8386b304b83aab877c469703bae50fd8150ac26a9cf5d730d4c90725bb673a97`。构建器以这份库为基础分别生成两份兼容旧版本的 HNR 变体，逐层核对摘要，并将加入间隔拍照逻辑的差分嵌入 `x6-mod-controls-prepare`。视频 HNR 默认使用原厂策略。

[间隔拍照自动曝光配方](../openx6/interval_ae_recipe.py)将静态拍摄的快门上限逻辑编入 `com.insta.stats.aec.so`。[SSD 配方](../openx6/ssd_recipe.py)为 `ins_configd` 和 `ins_bla` 重建存储选择分支，与 SSD 协调器的元数据共用[同一份布局](../recipes/ssd/layout.json)。三个成品分别与签名清单中的摘要核对。

[ADB 配方](../openx6/adb_recipe.py)重建守护进程、认证库和 systemd 单元。守护进程强制要求原生 ADB 认证，认证库读取 `/adb_keys` 中的持有者公钥，并关闭交互式添加公钥的入口。

### 怎样核对维护升级器

[升级器配方](../openx6/otad_recipe.py)编译[明文入口和版本检查](../recipes/otad/gate.S)。升级器只把指定私有暂存路径交给 `x6-owner-update-check`，加密包继续走原厂入口。主系统维护包校验通过后，原生版本比较允许同版本重装。降级需要校验器针对本包返回降级许可。SD 策略也接受结构和摘要正确的无签名明文包，按包版本和基准版本判定是否降级；已有签名记录但验签失败时会拒绝。桌面预览版保持安装锁定。

### 怎样核对工厂 USB 和 ADB

[USB 配方](../openx6/factory_usb_recipe.py)从官方镜像重建硬件服务、USB 接收程序和工厂 API 库。硬件服务允许选择 ADB 模式，切换前会检查旧接收程序是否正常停止。ADB 用持有者 RSA 密钥验证随机挑战；工厂命令单独使用 Ed25519 挑战。接收程序先检查载荷长度，[工厂认证入口](../recipes/factory_usb/factory_gate.S)对每条请求调用认证服务，成功后将带 15 字节内层包头的请求交给原生解析器。
